# 위원회 TAG 룰엔진 — 최종 성능 및 구조 정리

> 기준일: 2026-08-12
> 검증 방식: `backend/scripts/evaluate_tag_e2e_manual_llm.py` — 실제 프로덕션
> 파이프라인(`tag_pipeline.run_pipeline`)을 그대로 실행하고, Phase 2의 LLM
> 파싱만 Claude가 조문을 직접 읽고 대신 채운 "수동 LLM" 방식으로 대체했다.
> 정답 PDF는 이 스크립트가 직접 열지 않는다 — 비교는 별도로 사람이 수행했다.

## 1. 시스템 구조

```
PDF 원문
  → Phase 1 tag_router.py        조문이 비용유발 조문인지 라우팅
  → Phase 2 tag_parsers.py       조문에서 순수 변수 추출(정규식 우선, LLM 보조)
  → Phase 3 tag_rule_engine.py   DB 앵커링 고정 산식 계산(LLM 호출 없음)
  → Phase 4 tag_timeseries.py    연도별 시계열 전개
  → Phase 5 tag_formatter.py     최종 리포트 포맷
  → committee_evidence_adapter   Phase 3 이후, 선례 fallback 후처리
     (committee_component_recommender / committee_covered_estimator
      / committee_precedent_resolver, committee_evidence_v1 데이터 기반)
```

위원회는 조문 단위가 아니라 `committee_gate.py`가 "개체" 단위로 그룹핑해
한 번만 처리한다(설치·구성·운영 조문이 흩어져 있어도 중복계산 방지).

**중요**: `committee_channel.py`(lexical/hybrid 선례검색 모듈)는 이
파이프라인에 연결돼 있지 않다. 실제 선례 fallback은 별도의
`committee_evidence_v1` 데이터 계층을 쓰는 다른 어댑터를 통해 이뤄진다.
`server.py`는 아직 `tag_pipeline`을 호출하지 않는다 — 함수 자체는 완성돼
있지만 웹으로는 미연결 상태다.

## 2. 검증 규모

- 원래 50건 평가셋(수동 PDF 진단, 이전 세션에서 50/50 완료) 중 **44건**을
  실제 파이프라인 E2E 테스트로 재실행
- 위원회 엔티티 기준 **70개**(엔티티 자체가 감지 안 된 4건 별도)
- 이 중 약 **40건**을 실제 NABO 정답 PDF와 항목 단위로 직접 대조

## 3. 최종 결과 분포

| 상태 | 건수 | 비율 |
|---|---:|---:|
| `review_required`(확정값 없음, 범위 또는 보류) | 61 | 87% |
| 확정값(`calculated_*` 계열 전체) | 9 | 13% |
| 엔티티 자체 미검출 | 4개 의안 | - |

확정값 9건 중 정답 대조 가능했던 8건: **정확히 일치 2건, 근사(오차 30%
이내) 3건, 크게 틀림(4~50배 오차) 3건.** "확정값이 나왔다"는 것 자체가
안전을 보장하지 않는다 — 이게 이번 검증에서 가장 중요하게 확인된 사실이다.

## 4. 실제로 찾아 고친 프로덕션 버그 4건

| # | 버그 | 발견 경위 | 수정 |

4건 모두 특정 의안의 정답에 맞춘 수정이 아니라 일반 규칙(정규식·상태
전환 조건) 수정이며, 회귀 테스트 109개 중 108개 통과 상태를 계속
유지했다(1개는 무관한 기존 `estimator_v2` import 에러).

## 5. 실제 정답 대조 요약 (약 40건)

### 5-1. 맞음 / 범위 안 (약 10건)
2216065(정확 일치), 2214559(정확 일치), 2216353·2126145·2126659·2126679(범위
안), 2124966·2125736·2126334(범위 안), 2213848(근접, 1.5배 이내), 2213116·
2213188(근접, 30% 이내)

### 5-2. 근접하지만 벗어남 — 원인 규명됨 (3건)
2126636·2211757·2215199(전부 국회 자체 위원회, TYPE_4) — 인원수 추정은
정확했으나 1인당 단가가 "전체 공무원 평균"(봉급표 기준, 실수당 미포함)을
써서 14~34% 낮게 나옴 + "사업비"(17개 상임위원회 운영경비 평균, n=17짜리
검증된 정부 통계)라는 카테고리 자체가 누락됨. 둘 다 원인은 명확히
규명됐고 수정 여지도 있으나 미반영(n=17 사업비 평균은 안전, 단가 보정은
표본 확장 필요).

### 5-3. 확정값인데 크게 틀림 — "개소리" (3건)
- 2211774(법관평가위원회): 확정 1,000만원 vs 실제 250만원(4배 과대 —
  회의횟수 폴백 4회 vs 실제 연1회, 조문 밖 운영관행이라 원천 불가)
- 2213574(공무직위원회): 확정 2,400만원 vs 실제 12억원(50배 과소 —
  선례준용형, 회의수당 산식 자체가 안 맞는 방법론)
- 2126661(이태원참사특조위, 픽스처 버그 수정 후): 확정 60.4억원 vs 실제
  29.4억원(2.05배 과대 — 60명 중 14명이 파견인력인데 원소속기관이
  인건비를 지급한다는 사실을 몰라서 전원에 단가를 곱함. "파견인력은
  신규재정소요에서 제외한다"는 규칙은 로컬 DB에서 3회 확인된 일반
  원칙이지만, 몇 %가 파견인지는 사례마다 다름(83% vs 40%, n=2로 이미
  크게 벌어짐) — 규칙은 알아도 비율을 못 채움)

### 5-4. 완전히 다른 스케일 — 선례준용형/스코프 밖 (약 12건)
2215457(682억 vs 200만~700만), 2212535(76.75억 vs 300만~900만, 진화위
50% 준용), 2213937(99.62억 vs 900만~2,400만, 충청광역연합 준용),
2215954(966.7억 vs 1,500만, 국립의학전문대학원 설립비 자체),
2212912(5조1,838억 vs 900만~2,400만, 기본소득 지급액 자체) 등. 전부
"위원회가 법안의 핵심이 아니라 부수 요소"이거나 "정답이 다른 실제
기관의 실제 예산을 그대로 준용"하는 경우 — 회의수당 산식이 애초에
답할 수 있는 질문이 아니다.

### 5-5. "무엇을 셀지" 자체가 어긋남 (약 5건)
- 2124970(대전특별자치시): 감사위원회는 기존 조례로 이미 운영 중이라
  NABO는 재정수반요인에서 제외했는데 우리는 신설로 계산; 실무위원회는
  지원위원회 하위기구인데 독립 항목으로 이중 계산; 외국교육기관위원회는
  재량규정(다른 조문에 재량 근거가 있음)인데 확정 대상으로 계산
- 2212678(기후과학위원회): NABO는 회의수당 자체를 계산 대상에서 빼고
  "국가 탄소예산 산출"(5년마다 1회 용역비)만 계산
- 2215078(화재조사심의위원회): 중앙+시도 통합 1개 엔티티로 계산했는데
  실제로는 시·도 단위 복제설치 효과로 시도분이 중앙의 19배 — 복제설치
  로직이 안 걸림
- 2215198(국가미래위원회): 실제로는 전체회의+분과위원회 이중 구조인데
  조문에 분과위원회 언급이 없어서 우리는 단일 계산만 함

## 7. 결론

- **위험한 확정 오답을 내는 문제는 오늘 세션에서 실측 기반으로 상당히
  줄였다.** 발견된 버그 4건 모두 근거를 찾아 일반 규칙으로 수정했고
  회귀로 검증했다.
- **자동으로 정답에 가까운 숫자를 내는 비율은 여전히 낮다(확정값 13%,
  그중에서도 3/8이 크게 틀림).** 이건 대부분 원리적 한계(선례준용형의
  외부데이터 의존)에서 온다 — 튜닝으로 해결되는 종류가 아니라는 게
  이번 세션에서 여러 각도로(리트리벌 7종 실험 포함) 반복 확인됐다.
- **남은 개선 여지는 "탐지·라우팅 공백"에 집중돼 있다** — 복제설치,
  분과위원회 이중구조, 재량판정 위치, 엔티티 익명참조 해석 등. 전부
  조문 자체에서 뽑을 수 있는 신호이고, 오늘 패턴대로 하나씩 실측하며
  고쳐나갈 수 있는 종류다.

이 시스템은 "정답을 자동으로 낸다"고 부를 단계는 아니지만, "모르면
모른다고 말한다"는 안전 원칙은 실측으로 검증된 상태다.
