# ERCE: 추계 방법 선례와 변수 근거를 분리한 소량 실험

2026-10-03. 기존 ERCE 산식·계산기를 교체하지 않고 검색·검토 경계를 추가했다. README와 과거 첫 실행 기록은 변경하지 않았다.

## 현재 연결된 흐름

```text
PDF를 읽은 AI의 조문·변경내용
  → 추계 방법 선례 후보 검색(잠정 라우팅과 무관하게 검색)
  → 적용 조건·기존 비용·부담 주체·정책 가정 확인
  → 등록된 라우팅으로 고정 산식 선택
  → 부족한 변수별 DB 후보 검색
  → AI/사용자가 근거 ID를 선택하고 적용 이유 기록
  → 기존 근거 검증 및 Python 계산
  → 방법 선례·확인한 가정·변수 출처를 포함한 초안
```

검색 결과는 후보일 뿐이다. 같은 단어가 등장한다고 적용할 수 있는 방법이나 확정 단가가 되는 것은 아니다. 방법 검색은 현재 소량 데이터에 대한 키워드 묶음 검색이며, 벡터 검색이나 AI 의미 순위화는 구현하지 않았다.

## DB 구조와 재현

기존 `backend/generated/erce_variable_evidence.sqlite3`를 그대로 사용한다.

| 데이터 | 용도 | 현재 상태 |
|---|---|---|
| `erce_variable_evidence` | 단가·인원·비율 등 수치 근거 | 기존 검토 행 366건 유지 |
| `erce_official_salary_rates` | 공식 월 기본봉급 | 기존 516건 유지 |
| `erce_method_cases` | 적용 조건·부담 주체·기존 비용 확인 기준·가정·허용 산식 | 개발 검토 선례 4건 추가 |
| `erce_method_variable_links` | 방법에서 재사용 가능한 변수 근거로 연결 | 기본계획 용역 선례 1건 연결 |

새 방법 4건은 기본계획 용역, 입학금 폐지 보전, 단체 운영경비 지원, 학생대출 이자면제다. **뒤의 세 사례는 판단 방법만 등록했으며 부족했던 숫자 근거와 하위 계산까지 완성한 것은 아니다.** 금액·대상 인원을 방법 레코드에 복사하지 않았다.

```bash
python3 -m backend.erce.scripts.build_variable_table
python3 -m backend.erce.scripts.reference_snapshot export
python3 -m backend.erce.scripts.check_method_reuse
python3 -m unittest discover -s backend/erce/tests -q
```

공유용 `backend/erce/data/reference_snapshot.json`에도 방법 레코드를 포함한다. 기존 version 1 스냅샷은 그대로 가져올 수 있다. 방법-변수 연결의 참조 무결성과 스냅샷 복원도 테스트했다.

## 개발 중 AI 역할을 하는 방법

1. 대상 비용추계서는 열지 않고 의안 원문만 읽는다.
2. `find_method_candidates(query=조문과변경요약, cutoff_date=근거기준일, target_bill_no=의안번호, ...)`로 방법 후보를 찾는다. 검색을 잠정 비용유형으로 제한하지 않는다.
3. AI가 후보의 `baseline_check`, `payer`, `method_steps`, `limitation`을 읽고 적용 여부를 판단한다. 후보가 없거나 적용 조건을 확인하지 못하면 보류한다.
4. 적용할 방법에는 `selected_method_keys`, `method_selection_reasons`, `method_confirmations`, `payer`를 기록한다. 등록된 `allowed_routes` 밖의 산식에 연결하면 오류다.
5. `find_variable_candidates` 또는 웹 계산의 `referenceCandidates`에서 변수별 숫자 후보를 찾는다. 단위·기준연도·대상집단·지원 기능·통계 범위·실적/전망/상한의 차이를 AI가 확인한다.
6. `selected_evidence_keys`와 `evidence_selection_reasons`를 입력한다. HTTP 요청의 임의 DB 경로와 직접 주입한 공식·선례 수치 레이어는 사용하지 않는다. 서버가 지정한 DB에서 선택한 ID의 값을 읽는다.
7. 불확실한 정책 실시·부담 비율·대리값은 사용자 확인 가정으로 남긴다. 의안 명시값은 선례 값보다 우선한다.
8. 계산과 초안 생성 뒤에 정답을 열어 대상 범위·산식·변수·금액을 비교한다. 보강 후 같은 의안을 다시 계산한 결과는 독립 평가로 보고하지 않는다.

`no_incremental_cost` 또는 잠정 산식이 검색된 방법 후보와 충돌하면 PDF 분석 결과를 `needs_review`로 남긴다. 이 규칙은 비용 발생을 확정하거나 새 산식을 자동 선택하는 규칙이 아니다. 이미 지원하던 사업비와 새 운영비의 범위를 비교하도록 만드는 안전장치다.

### 평가 제외

- 방법과 변수 모두 자기 의안의 정답 근거를 웹 계산에서 제외한다.
- 기준일 이후 자료를 제외한다. 공식 자료도 현재 최신이라는 이유로 과거 평가에 주입하지 않는다.
- 방법의 동일 계열 제외는 `target_family_key`가 제공될 때 작동한다. 모든 의안의 계열을 자동 구축한 상태는 아니다.
- 같은 계열 의안번호 목록은 `excluded_bill_nos`에 전달해 방법·변수 검색과 선택에서 모두 제외한다.
- 방법/단가의 검색 후보 존재와 실제 적용 가능성을 혼동하지 않는다.

## 실제 의안 연결 확인: 2217718

인공지능 데이터센터 법안의 제5조제1항만 읽어 실행했다. 이번 실행에서 대상 비용추계서는 열지 않았고 API도 호출하지 않았다. 과거에 다뤘던 의안이므로 새 독립 평가가 아닌 연결 회귀검증이다.

- 7쪽 조문 인용 확인. `5년마다`에서 계획 주기 5년을 추출했다.
- 발의일 2026-03-24 이전의 2200039 기본계획 연구용역 방법이 후보로 검색됐다.
- 처음에는 용역단가 1개가 부족했고, 기존 2.03억원 단가가 후보로 제시됐다. 자동 확정하지 않았다.
- 개발용으로 **외부 용역 실시, 2027년 첫 수립, 과거 가격 동결**을 명시해 선택한 뒤 기존 계산기와 웹 경계를 통과시켰다.
- 시나리오 계산 결과: 첫해 203,000천원, 이후 4개년 0천원. 초안까지 생성됐다.

**이는 AI 데이터센터 계획의 적정 비용이 2.03억원임을 검증한 결과가 아니다.** 부처·과업·규모가 다른 과거 용역 가격의 적용 타당성, 현재 가격 환산 및 실제 시작연도는 확인되지 않았다. 전체 법안의 나머지 조문도 이번 실행에서 분석하지 않았다. 결과는 `cases/ERCE_METHOD_REUSE_2217718.json`에 기록했다.

## 아직 남은 것

- 현재 GPT PDF 분석 호출은 기존 1차 구조화 분석이다. 검색 후보를 받아 **GPT가 다시 적용 여부를 판단하고 근거 ID까지 자동 선택하는 단계는 아직 연결하지 않았다.** 개발에서는 에이전트가 이 역할을 한다.
- 기존 채팅 UI 전체가 방법 선택과 DB 근거 ID 선택을 지원하도록 바뀐 것은 아니다. 이번에는 Python 함수와 기존 웹 계산·초안 API의 수용 경계를 연결했다.
- 전체 의안 계열 묶음, 변수별 단위 검사의 완전한 표준화, 후보 검색 누락률 및 독립 금액 정확도 평가가 필요하다.
- 이자면제의 잔액×금리, 단체 운영비의 단체 수×연간 단가 등 하위 계산과 숫자 근거는 별도 보강해야 한다.
