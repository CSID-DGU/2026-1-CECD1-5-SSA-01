# ERCE 재사용 변수·단가표

## 범위와 위치

로컬 SQLite: `backend/generated/erce_variable_evidence.sqlite3`.
2026-09-27 검토한 **57개 변수 근거**를 적재. 기존 전체 사이드카는 변경하지 않았다.
전체 문서를 새 DB로 재적재한 것은 아니다.

재구축·확장 명령: `python3 -m backend.erce.scripts.build_variable_table`.
검토한 근거를 `reviewed_variable_rows.py`에 출처별 새 버전으로 추가하고 실행한다.
같은 근거 ID 재실행은 중복 적재하지 않으며 다른 근거를 삭제하지 않는다.

## 행에 보존하는 정보

각 행은 금액뿐 아니라 다음을 보존한다.

- 산식 변수명, 값, 단위, 역할(단가/가정/규모/기존 비용/사업계획/한도).
- 업무 목적, 대상 집단·지역·채널, 기관, 정책 도메인, 비교 사업 규모.
- 가격 기준연도, 관찰연도, 배열의 적용연도, 적용조건·물가 전망 가정.
- 의안번호, 문서 페이지/표, 공개일, 출처 링크, 검토일, 한계.
- 재사용 정책: `comparable`(적용 가능성 판단 필요), `same_scope`(동일 범위만),
  `target_only`(해당 의안 전용). 공식 지급 상한은 `constraint`로 별도 저장.

전국 수입액·지원 인원 같은 값은 단가로 취급하지 않는다.
사업 ISP 총예산은 다른 시스템 견적의 단가로 전용하지 않는다.
가격연도 전망 배열은 연도가 달라지면 거부하며 자동으로 '최신'이라고 부르지 않는다.
공식 기준은 적용 가능한 원문을 확인했을 때만 공식값으로 저장한다.
선례에서 지침을 인용했다는 이유만으로 공식 고정값으로 승격시키지 않는다.
공식 지급 상한을 지급액으로 곧바로 넣는 것도 거부한다.

## 실제 연결

1. AI가 법안의 비용 항목과 라우팅 트리의 산식 잎을 고른다.
2. `find_variable_candidates`로 변수별 후보·메타데이터를 확인한다.
   기관·도메인은 선택 필터이며, 비슷한 다른 도메인 후보도 변수명으로 찾아볼 수 있다.
3. AI가 적용 가능한 근거 ID를 `selected_evidence_keys`로 지정한다.
   다른 기관·대상 범위의 선례를 쓰려면 적용 이유도 기록한다.
4. 엔진은 근거를 DB에서 읽고 공개일, 대상 정답, 적용연도, 전용 범위를 검증한다.
   소급 사망자 수량은 별도 소급 적용 근거가 없으면 거부한다.
5. 법안 명시값→대상 실제자료→적용 가능한 공식값→앞 단계 계산값→선례 가정 순으로 채운 뒤 계산한다.
   앞 단계 계산값은 실제 지출과 구분하고, 가정에 의존했는지도 표시한다.

이 테이블은 후보를 자동으로 '가장 유사하다'고 선정하지 않는다. 판단은 AI 역할이다.
일부 이전 경로의 호환 레지스트리는 유지하고, DB ID 선택은 실제 엔진에 연결했다.

후속 [2200936 사례](cases/ERCE_CASE_2200936.md)에서 협의체 회의1회 비용과 연간 운영비를 별도 경로로 분리했다.
같은 통일부 협의회 연간예산·가격 기준연도 해석·물가 전망의 출처를 저장했다.
정답 확인 후 DB 근거 선택으로 재계산한 합계57,600천원, 공개 정답 대비 오차2.86%.
첫 실행240,000천원의 실패는 그대로 보존하며 신규 추계 성능에 보강 결과를 섞지 않는다.

후속 [2215199 사례](cases/ERCE_CASE_2215199.md)에서는 국회의원 참석수당 후보를 제외하고,
지원직원·기관부담금·기본경비·첫해 자산·연간 사업비를 분리했다.
같은 국회 위원회라도 예결산 예비심사 권한과 직급구성이 다르면 인원·급여 가정을 그대로 빌리지 못하도록 보강했다.
최초67.81억원(오차38.96%), 정답 근거 보강 후48.88억원(오차0.17%)을 분리해 보존한다.
후자의 보수·인원은 대상 정답에서 보완한 근거이며, 다른 법안에서는 업무·직급·연도 적합성 판단을 거쳐야 한다.

네 사례는 공개 정답에서 보완한 관찰값을 `development_review`로 재사용한 결과이다.
이는 **저장→선택→계산 연결 검증**이며 독립 신규 추계 성능이 아니다.
검토한 자기 문서도 개발 재검증에서는 쓸 수 있지만 기본 `holdout` 모드에서는 거부한다.
문서에 수량·단가를 수동 입력한 옛 산술 재현과 구분한다.
사건 수 전망의 기준연도 불일치나 ISP 원본 독립 확보까지 해결했다고 주장하지 않는다.

## 이식성

키·변수명·기관·도메인·범위·공개일·의안번호는 일반 SQL 열,
추가 메타데이터는 JSON 문자열이다. SQLite 전용 의미 검색이나 확장 함수를 쓰지 않는다.
Supabase 이관 시 JSON 문자열을 JSONB로 변환할 수 있다. 실제 원격 이관은 수행하지 않았다.
