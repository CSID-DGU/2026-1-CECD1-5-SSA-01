# 개발일지 2026-08-05

위원회 TAG 룰엔진 — 위원회_평가셋(50건) 실측 검증 중 발견·수정한 문제들.
"LLM이 조문에 명시된 걸 잘 가져다 쓰는가"를 확인하다가 발견한 것들이라,
전부 실측(실제 정답지 대조 또는 라이브 API 호출) 기반이고 추측 없음.

---

## 핵심 결론 한 줄

```
"규칙(정규식)이 조문의 명시적 표현을 놓치고 있진 않은지"를 감시하는
진단 레이어(extraction_mismatches)를 만들고 나서 돌리자마자, 실제로
규칙이 놓치던 표현 2개("N인" 카운터, "N명 이상"만 있는 표현)를 실측으로
잡아냈다. 또한 "LLM을 신뢰할 수 있는가"는 작업 종류가 아니라 작업
범위(좁은 단일판단 vs 넓은 다중개체 처리)로 갈린다는 게 같은 모델
기준으로 재확인됨(그루핑=실패, 단일판별=3/3 성공).
```

---

## 1. 규칙(정규식) vs LLM 불일치 진단 레이어 추가

`CommitteeVars.extraction_mismatches` — 계산에는 안 쓰이는 순수 진단 필드.
규칙이 값을 못 찾았는데 LLM은 뭔가 찾은 경우(`rule_missed`), 또는 둘 다
찾았는데 값이 다른 경우(`value_mismatch`)를 매 의안마다 자동으로 기록.

- 파일: `backend/tag_parsers.py` (`extract_committee_vars`)
- 목적: "조문에 명시된 걸 규칙이 잘 가져다 쓰는가"를 사람이 매번 눈으로
  검토하지 않고 자동으로 감시.

## 2. "OO인" 카운터 표현 — 정규식이 "명"만 잡던 문제

**실측(2126334, 국립대학병원법)**: 조문 "공동위원장 2인을 포함한 25인
이내의 위원으로 구성한다"에서 "인"이 옛 한자어 표기라 정규식이 아예
못 잡음 (`_SIZE_CAP` 등 세 패턴이 전부 "명"만 허용).

- 수정: `_CNT = r"(?:명|인)"`으로 통합 (`backend/committee_size_extract.py`)
- 검증: `extract_committee_size("...25인 이내의 위원...")` →
  `{'kind': 'cap', 'value': 25}` 확인.

## 3. "위촉 N명" 직접 추출 — ex_officio 경유 없이 유급위원 확정

**실측(2216065)**: "위촉하는 사람 5명"처럼 유급위원 수 자체가 조문에
명시된 경우, 기존엔 `총원 - 당연직`으로 계산했는데 당연직이 LLM 판단
영역이라 비결정적이었음. `extract_paid_member_count()` 정규식으로
직접 확정해 우회 — 정답(500만원)과 정확히 일치.

## 4. paid_members 폴백 — 검증 안 된 가정 → 실측 구간 → 법정 문구 반영

3단계로 재작업(`backend/tag_rule_engine.py::_meeting_cost`):

1. **문제**: 당연직 수를 모를 때 `[총원-1, 총원]`(당연직 최대 1명 가정)을
   썼는데, 검증 없이 박혀있던 가정이었음. 실측(2126334: 총원25명 중
   실제 당연직 14명, 56%)으로 완전히 틀렸음이 확인됨(정답 1,100만원인데
   range가 2,400만~2,500만원 — 정답을 아예 못 잡음).
2. **수정 1**: 로컬 TAG DB에서 "총원 N명 중 유급 M명"이 직접 쌍으로
   나오는 8건을 정규식으로 채굴 → 비율 33~80%(n=8) → `PAID_MEMBER_RATIO_RANGE`.
   재검증: range가 정답(1,100만원)을 포함하도록 개선됨.
3. **수정 2(외부 리서치 교차검증)**: 정부입법지원센터 「법령입안심사기준」에
   "민간위원이 과반수가 되도록 하여야 한다"는 표준 조건부 문구가 실재함을
   웹서치로 확인(국민통합위원회 39명/당연직10명=유급74.4%도 실측 확인,
   33~80% 구간 내 부합). 조문에 이 문구가 실제로 있으면 하한을 50%로
   확정하는 `extract_paid_member_ratio_floor()` 추가.

## 5. "OO명 이상"(상한 없음) 표현 — 규칙이 아예 못 잡던 3번째 사이즈 패턴

**실측(2126635, 헌법개정절차법)**: "30명 이상의 위원", "500명 이상의
국민참여위원"처럼 하한만 있고 상한이 없는 표현 — 기존 `_SIZE_RANGE`
("이상...이하" 둘 다 필요)도 `_SIZE_CAP`("이내")도 커버 못 함.

- NABO 실제 관행: 명시된 최솟값을 그대로 점추정치로 사용.
- 수정: `_SIZE_MIN` 패턴 추가, `kind="min"`으로 반환.
- 검증: 자문위원회(30명×25만원×4회=3,000만원)와 국민참여회의
  (500명×25만원×1회=1억2,500만원) **둘 다 정답과 원 단위까지 정확히 일치**.

## 6. LLM 기반 위원회 그루핑 — 라이브 테스트로 실패 확인

같은 법안(2126635)에 이름이 비슷한 위원회가 3개(헌법특별위원회/
자문위원회/국민참여회의) 뒤섞여 있을 때, 기존 정규식 그루핑
(`committee_gate.py`)이 이름을 파편화/오매칭(예: "의구성및운영자문위원회").

- `committee_channel.py`에 이미 있던 "LLM 제안 + 근거검증(grounding)"
  하이브리드 그루핑(`_group_committee_articles_hybrid`)을 실제 프로덕션
  모델(Upstage `solar-pro3`)로 라이브 호출해 확인.
- **결과: 정규식보다 더 나빴음.** 신설된 2개는 후보에도 못 올리고, 참조뿐인
  엉뚱한 위원회 1개만 제안(그마저 근거검증에서 정상적으로 걸러져 최종 0개).
- 결론: 이 규모/모델로는 "긴 문서에서 여러 개체를 동시에 식별·구분"하는
  작업을 못 맡긴다 — 세션 초반 "solar 계열 오차 +124~588%" 발견과 같은 결.

## 7. LLM 기반 아키타입 판별 — 같은 모델로 라이브 테스트, 이번엔 성공

**대비 실험**: "위원회 하나를 두고, 위원이 국회의원 자신인지"(좁은 범위,
근거가 근처에 문자 그대로 있음)만 물었더니 같은 모델(`solar-pro3`)이
3/3 정확(양성 1건+음성 2건), 인용 근거도 원문 그대로.

- → **결론**: LLM 신뢰 여부는 "읽기 vs 계산"이 아니라 "판단 범위가 좁은가
  넓은가"로 갈린다. 안전장치(인용 근거가 원문에 실제 있는지 검증)는
  둘 다에 유효.
- 구현: `committee_assembly_internal_gate.py` — LLM 판별 + grounding
  (조사 1~2개 누락 정도는 허용하되, 실질 내용은 원문 그대로여야 통과).
  실측 버그: 최초 완전일치 검사가 "의" 조사 하나 누락으로 실패 → 조사
  제거 후 비교로 완화.

## 8. 4번째 아키타입("국회 자체 특별위원회") 구현 — n=2 확인 후 게이트화

**실측 n=2**: 2211757(위원15명, 지원인력6명=40%), 2126636(위원30명,
지원인력15명=50%). 위원=국회의원 자신이라 참석수당 개념이 없음(세비로
이미 지급) — 실제 비용은 사무처 소속 지원인력(전문위원/입법조사관 등)
인건비.

- `TYPE_4_ASSEMBLY_INTERNAL` 추가, 산식: 참석수당 미적용, 지원인력 =
  위원정수 × 비율(40~50%, n=2) → 인건비 계산.
- 검증(2126636): range [10.8억, 13.5억] vs 정답(인건비만) 15.0~15.8억원.
  **오차: 하한 -28~30%, 상한 -10~13%.** 아키타입 오분류를 피한 덕에
  자릿수(억 단위)는 맞았지만 정밀하진 않음 — range가 정답을 완전히
  못 담음.
- **원인 분리**: 지원인력 "비율"(상한 50%=15명)은 실제 인원과 정확히
  일치 — 갭은 비율이 아니라 그 다음 단계(직급 불명 시 인건비 단가 계산)
  에서 발생.

## 9. 발견한 공유 이슈(위원회 전용 아님) — 직급 불명 인건비 폴백 과소평가

8번의 잔여 오차를 추적하다가, `AVERAGE_STANDARD_INCOME_ANNUAL_2026`
("전체 공무원 평균") 폴백이 국회 전문위원/입법조사관처럼 중간~고위
직급 위주 조직엔 체계적으로 낮게 나온다는 걸 확인.

- **범위 확인**: `calculate_personnel()`/`_personnel_cost_from_salary`는
  TYPE1(중앙행정기관 소속공무원)·TYPE2(사무국 직원)·TYPE4(지원인력)
  위원회뿐 아니라, 위원회와 전혀 무관한 "공무원 정원 증원" 카테고리
  (`tag_pipeline.py`의 "1_인건비_물건비" 분기)에서도 공유되는 범용
  유틸리티임을 코드로 확인.
- **미해결**: n=1(이 건)만으로 보정계수를 만들면 끼워맞추기라 보류.
  다음에 이 폴백 경로를 타는 사례가 더 쌓이면 재검토.

## 10. 2126659(가족돌봄아동·청소년·청년법) — range 방식 정상 작동 확인

총원 15명(cap, 정규식 정확) / 당연직 수 불명 → ratio_fallback_n8 range
[4~12명] → 비용 range [400만~1,200만원]. 정답(10명×20만원×4회=800만원)이
이 range 안에 정확히 포함됨(True) — "정직한 불확실성" 방식이 실제로
작동한 사례.

**부수 발견(미해결, n=1)**: NABO가 이 건에서 쓴 단가가 20만원인데,
이 위원회는 보건복지부 소속이고 사법부와 무관함 — 지금 코드는 20만원을
"사법부(대법원) 전용 지침"으로 분류하고 있다(`UNIT_COST_JUDICIARY_WON`).
20만원이 실제로는 "기획재정부 지침 원안 그대로"(사법부 여부와 무관)이고,
25만원 쪽이 "실무 관행으로 얹은 값"일 수 있다는 의심. 이 건은 range
계산이라 결과에 영향은 없었지만, 다음에 비슷한 사례(비사법부인데 20만원)가
더 나오면 `select_attendance_fee()`의 "judiciary" 라벨링 자체를 재검토.
