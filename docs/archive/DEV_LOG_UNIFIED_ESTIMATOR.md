## 최근 검증 — 미첨부 사유의 누락 변수 역할 게이트

**관측한 실패**: 미첨부 사유서 검색 방향은 맞았지만, 절대 임베딩 유사도
`0.48` 하나로 자동 보류 여부를 정해 의미적으로 적절한 과거 선례가
`0.459`라는 이유로 판정에 쓰이지 못했다.

**일반화한 수정**:

1. 임베딩은 미첨부 문서 후보 검색에만 사용한다.
2. 구조화된 공식 사유 417건을 `조직·인력 규모`, `시설·공간 규모`,
   `지원 대상 규모`, `단가·지급 기준`, `수요·처리 건수`,
   `사업 시행 범위`, `기초 실적자료` 역할로 정규화한다.
3. 현재 계산 행이 실제로 기다리는 역할과 과거 미첨부 사유의 역할이
   일치할 때만 반대 근거로 인정한다.
4. 이미 계산된 행은 바꾸지 않고, 미확정 행만 `needs_evidence`로 전환한다.
5. 대상 의안 자체와 대상보다 미래인 미첨부 문서는 검색 풀에서 제외한다.

**독립 검증**: 미첨부 사유서가 정답인 2126667을 대상으로 자기 사유서를
제외하고 과거 선례 2124766(조직·인력 규모)과 2124179(시설·공간 규모)를
선택했다. 모든 13개 행을 `needs_evidence`로 유지하고 자동 계산 행은
0건이었으며, 대상·미래 문서 누출도 0건이었다. 이는 비용이 0원이라는
판정이 아니라 순증 인원·기관 수·시설 범위를 확인하기 전 계산을 보류한
것이다.

**회귀**: 기존 금액 검증 7건은 모두 허용 오차를 유지했다.
리포트: `/private/tmp/estimator_v2_v21_role_non_attachment.json`.

**남은 범위**: 이번 자동 승격은 조직·시설 규모 미확정 사례에 우선
연결했다. 기술적 곤란(B) 404건 중 역할이 아직 구조화되지 않은 115건과
조세·지원사업 등 다른 비용유형의 최종 게이트는 후속 사례 검증으로
확장한다.

## 1. 목표

- 위원회 전용(`committee_channel.py`)을 넘어 **모든 비용유형(위원회·사무처/인건비·사업비/지원금·시설 등)에 대응**하는 하나의 구조.
- **자가발전 하네스**: 의안을 하나씩 돌려 정답지(공식 비용추계서)와 비교 → "왜 다른지, 어디서 문제가 발생했는지" 진단 → 일반화된 구조 개선 → 다음 의안.
- 제품 포지션은 "사람이 검증하는 초안". 목표는 **정확한 수가 아니라 "리즈너블 + 근거추적 + 사용자수정 가능"**.

## 1-A. 목표 아키텍처 (큰 틀) — 테이블 생성 파이프라인

출력물은 **비용추계서 테이블**(행=비용항목, 열=5개년+합계+연평균). 따라서 파이프라인은
"각 비용항목(행)을 감지 → 산식 붙임 → 변수 채움 → 셀 계산"으로 흐른다.
**베이스는 analyzer_v2** (감지·라우팅·산식 레지스트리를 이미 보유).

```
PDF → 조문 파싱 → holdout(본인/미래 제외)
  → [1] 비용항목 감지        : 조문 → 비용유발 실체/항목 (LLM, 실체 단위 그룹핑; 한 항목이 여러 조문에 걸칠 수 있음)
  → 각 항목마다:
      [2] 유형 라우팅        : infer_template_key() → 위원회/인건비/용역/지원금/기관부담금/기본경비/자산취득/조세감면
      [3] 표준산식 선택      : assembly_formula_templates.py 레지스트리 (유형별 표준 산식)
      [4] 변수 해결(핵심)    :
            · 원문 명시값     → 파싱(결정적)
            · 표준·상수       → 회의수당 단가, 행정구역 수(시·도 17/시·군·구 229) 등 재사용 상수
            · 선례 기반       → representative value(대표값 5조건, 비율보정)
            · 복제(×N)        → _replication_factor
            · 외부데이터      → 채울 수 있으면 채우고(통계), 아니면 HITL 플래그(대상자 수·정책단가)
      [5] 셀 계산           : 결정적(연도별 × 복제배수)
  → [6] 테이블 조립         : 항목 × 5개년
  → [7] grounding 게이트     : 근거 없는 항목 제거(과잉생성 방지)
  → [8] QA·근거추적 + HITL 상태(computed / review_required / blocked)
```

**단계별 현황(대부분 analyzer_v2에 이미 존재):**
| 단계 | 상태 | 개선 포인트 |
|---|---|---|
| [1] 감지 | 있음(범용) | **2건(2126659·2126660) 위원회 0개 실패 → 로버스트니스** |
| [2] 라우팅 | 있음(8유형) | 오라우팅 점검 |
| [3] 산식 레지스트리 | 있음 | 누락 유형(일회성 등) 보강 |
| [4] 변수 해결 | **부분 — 핵심 개선영역** | committee의 대표값 깊이 흡수 + ×N 이식 + 외부 플래그 정리 |
| [5] 계산 | 있음 | 복제배수 반영 |
| [6] 테이블 | 있음 | — |
| [7] grounding | 있음 | 과잉생성 억제 |
| [8] QA/HITL | 있음 | — |

**측정 기준(총액 아님):** ① 항목 뼈대 완전성(감지·라우팅 정확도) ② 도출가능 항목 금액오차 20% ③ 외부데이터 항목의 HITL 플래그 정확도.
**committee_channel**: 깊은 위원회 변수해결(+×N)을 [4]로 흡수 후 은퇴 대상.

## 2. 핵심 결정과 원칙 (바뀌면 여기 갱신)

1. **몸통 = `analyzer_v2.py`, 엔진 = `committee_channel.py`.**
   - analyzer_v2가 이미 통합 파이프라인(조문 순회 → LLM 판단 → 유형별 builder 디스패치 → grounding → QA). committee_channel은 그 위원회 부분을 포크한 중복.
   - 방향: committee_channel의 깊은 변수해결(allowlist 산식선택 + 변수별 대표값)을 analyzer_v2의 **항목별 전략**으로 흡수. 채널을 늘리지 않는다.
2. **분류·라우팅은 "의안 단위"가 아니라 "항목 단위".**
   - 한 의안에 여러 비용유형 공존(예: 전문위 + 사무처). 항목마다 유형 분류 → 항목별 엔진 호출 → 합산.
3. **변수 라우팅(항목 안에서):**
   - 원문 명시값 → 파싱(결정적)
   - 표준값(회의수당 단가·집행률) → 선례 대표값(자동)
   - 컨텍스트값(지원 대상자 수 등) → 외부데이터(통계) 또는 HITL. **자동 불가하면 정직하게 "무슨 외부데이터 필요"로 표시.**
4. **규칙 vs LLM 배치 원칙:**
   - 검증·정책(holdout·grounding·allowlist·대표값·중복제거) = 규칙 (재현성·설명가능성). 유지.
   - 표준 법령문법 파싱(개정문 등) = 규칙, 유한하니 수렴. OK.
   - 열린 의미판단(비용유발 여부·산식 선택·성격) = LLM. (규칙으로 하면 트레드밀)
5. **정답 튜닝 금지.** 특정 금액에 맞추는 magic number 금지. 오답의 구조적 원인만 일반화 수정.
6. **평가 규율:**
   - **간호법(의안 2126640)은 평가 금지** — 과거 오버핏. 결과 부풀려짐.
   - holdout은 `bill_no`만 제외 → 같은 법률 다른 발의버전(**쌍둥이, 같은 bill_name**)은 near-leak. 정직한 수치 원하면 bill_name 단위 제외.
   - **조직설치 의안은 위원회 총액으로 평가 금지** — 비용 대부분이 사무처 인건비·사업비(위원회 범위 밖). 위원회 엔진은 공식의 **위원회 라인아이템**하고만 비교해야 공정.
   - **오라클변수 시험 vs 블라인드 시험 구분**:
     - 블라인드 = 외부값 안 줌 → "스스로 얼마나 추계하나".
     - 오라클변수 = 정답지의 외부값(대상자 수 등)을 넣어줌 → "**올바른 입력 주어지면 구조·산식·계산이 맞나**". 블라인드라 부르면 누출. 라벨을 정직히.

## 2-A. 새 구조 — `backend/estimator/` 패키지 (진행 중)

결정: **깨끗한 범용 엔진 = committee 엔진을 위원회 전용 가정만 걷어내고 일반화.** 새로 짜는 게 아니라 검증된 로직을 유형 무관하게 추출. 인프라(PDF파싱·RAG·임베딩·holdout·grounding·**DB의 TAG 구조**)는 재사용.

**핵심 설계 원칙 (사용자 확정, 절대 어기지 말 것):**
- **산식은 하드코딩 표준메뉴 X, LLM 작문 X → DB(TAG 실제 선례 비용추계서)에서 검색 → LLM이 조문 "의미"를 이해해 allowlist에서 선택.** (표준산식 레지스트리 접근은 폐기 — "규칙 기반·글자겹침"이라 반려됨. `assembly_formula_templates.py`는 나중 fallback용으로만 보존.)
- **변수값도 DB 선례에서** 적절한 대표값(표준값=최빈값 / 규모의존=비율보정 중앙값)으로. 없으면 외부데이터/HITL.
- LLM의 역할 = **의미 파악**(어떤 비용인지, 어떤 산식이 맞는지 선택). 규칙/글자매칭으로 하면 안 됨.

## 2-B. 범용 엔진 구현 현황 (estimator/ — 실제 돌아감)

파이프라인: **PDF → 조문 → [감지 LLM] → [추계가능성 LLM] → [TAG 산식·금액 결정적] → [역할 계산] → 테이블**

| 파일 | 역할 | 상태 |
|---|---|---|
| `types.py` | 도메인 모델 | ✅ |
| `detect.py` | [1] LLM 의미 기반 비용항목 감지(표준산식/채널 없음) | ✅ 위원회+용역+인건비 등 다 잡음 |
| `spec.py` | [2] 추계가능성 판정(LLM) | ✅ NABO 기준: **미정규모·임의규정 제외** |
| `tag_db.py` | [3] 원본 TAG(3,346항목)에서 산식+금액 결정적 조회 | ✅ 홀드아웃(bill_no/법률명/제안일) |
| `resolve.py` | ×N 복제 + 대표값 | ✅ |
| `pipeline.py` | [5] 역할 기반 계산 + 조립 | ✅ 단위폭발 구조적 차단 |
| `run_estimator.py` | 실행+오차+단계 진단 하네스 | ✅ |

**해결한 것(전부 일반적, 끼워맞추기 아님):**
- **단위 폭발**: 역할(count/unit_price/amount/rate) 기반 계산 — 단가 2개↑면 계산보류. 임의상한 없이 구조적 차단.
- **추계가능성**: "비용이 미정규모(인원·기관수)에 비례하는데 조문에서 확정 못 하면 기술적 곤란" = NABO 일부추계 원칙.
- **원본 TAG 1차 사용**: 12키 파생풀 대신 raw TAG(formula_text 12,595건 포함). 같은 질의 → 같은 값(결정적).
- **홀드아웃 누출 수정**: raw TAG에 struct→bill_no/법률명/제안일 매핑 붙여 본인·쌍둥이·미래 제외. (이전엔 대상 의안 정답이 그대로 매칭됐음 — 심각 누출이었고 해결)

**남은 핵심 난제 — 매칭 정밀도(2126334 총액 아직 안 맞음):**
- **토큰겹침 amount-analogy는 정밀도 천장**이 있음: 용역/계획은 잘 맞으나(100백만 ≈ 공식 106), **위원회는 부정확**(~66 vs 공식 11) — 조문의 실제 위원 수(11명)를 안 쓰고 유사 항목 평균을 써서.
- 토큰 문턱 튜닝은 한 실패↔다른 실패(위원회 82↔289). IQR 이상치 제거는 도움되나 부족.
- **정답 방향**: 구조화 유형(위원회)은 **분해 해결**(조문의 위원 수 × 유사 수당단가)로, 집계 유형(용역/계획)은 amount-analogy로. + 임베딩 기반 매칭.

## 5. 지금까지의 핵심 발견 (진단)

1. **-99% 과소추계는 버그가 아니라 스코프/커버리지 문제.** 조직설치 의안 비용의 대부분이 사무처 인건비·사업비인데 committee_channel은 회의수당만 계산. → "여러 비용유형 항목이 합산되는 통합 구조"가 필요하다는 데이터 증거.
2. **analyzer_v2가 구조적으로 우월.** 2126679에서 위원회 4개 + **지원 항목 2개(적정임금·휴업수당)**까지 찾음. committee_channel은 지원 항목을 구조적으로 못 찾음.
3. **지원 항목 금액이 None인 건 엔진 부족이 아니라 "변수 성격" 문제.**
   - 대상자 수 = 컨텍스트값(매 의안·연도마다 다름) → 선례 대표값 불가, 외부통계/HITL 필요.
   - 단가·집행률 = 정책 가정 → 데이터로 못 채움, 가정/HITL.
   - analyzer_v2가 이를 `source_type=external_data`, `needs_user_confirm=true`로 플래그한 것은 **올바른 행동**.
4. **committee_channel도 대표값 로직 있음**(`target_excluded_corpus_mode`, 119건 최빈값). analyzer_v2도 위원회 변수는 자동으로 채움. → "committee 엔진이 유일하게 깊다"는 초기 인상은 과했음. 진짜 우위는 committee의 변수해결 **정교함**(비율보정·5조건 대표값)이지, 자동화 유무가 아님.

### 5-1. 항목단위 진단으로 밝혀진 것 (2126679, `diagnose_items.py`) — 총액 기반 오진 정정

총액 비교(-99%)로는 "사업비 때문, 외부데이터 필요"로 **오진**했으나, 항목 단위로 보니 진짜 원인이 달랐다:

1. **[최우선] 지역위원회 복제(×N) 스케일 부재 — 294배 과소.**
