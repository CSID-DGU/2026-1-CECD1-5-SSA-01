# 개선 기록 (Engineering Log)

> 실제 의안을 넣고 NABO 원본과 비교 → 오답 진단 → 일반화된 구조 개선 → 현재 의안을 제외한 회귀 확인.
> 이 문서는 target-excluded 개발 holdout 기록이며, 엄격히 분리된 블라인드 성능 벤치마크가 아닙니다.

## 사이클 1 — 미첨부 판단 채널의 부재 발견

**문제**: 중대범죄수사청 설치법(2217239)을 분석하자 27억 원을 산출. NABO 정답은 **미첨부 3호**(조직구조·정원이 전부 대통령령 위임이라 추계 곤란).

**진단**: 시스템이 "산출" 방향은 RAG/TAG 데이터 기반으로 판단하지만, "미첨부" 방향은 판단 채널 자체가 없었음. 미첨부 사유서 데이터 5,800여 청크를 보유하고도 어디에도 연결하지 않은 **구조 불균형**.

**개선**:
- 조직 신설 + 대통령령 위임 다수 + 구체 정원 미명시 → 미첨부 3호 후보 정책 신설 (`organization_delegation_heavy`)
- verdict 게이트에 미첨부 우세 판단 추가

**검증**: 중대범죄수사청 → 미첨부 3호 정답 전환 ✅

## 사이클 2 — 규칙의 오버피팅과 Dual-Channel 전환

**문제**: 거의 동일한 패턴인 공소청 설치법(2217240)이 다시 산출(11억)으로 오답. 사이클 1의 규칙이 특정 케이스에 오버피팅된 것.

**진단**: 규칙 기반 접근은 케이스 하나를 잡으면 다음 케이스를 놓침. 근본 원인은 **미첨부 판단이 데이터 기반이 아니라는 것**. 사전 실험으로 공소청 조문을 임베딩해 미첨부 채널을 검색하자, **자기 자신의 미첨부 사유서가 유사도 0.729로 정확히 매칭**됨을 확인.

**개선** — Dual-Channel kNN Verdict:
- 조문마다 유사 비용추계서 채널(A)과 유사 미첨부 사유서 채널(B)을 동시 kNN 검색
- 채널별 유사도 비교로 미첨부 신호 산출 (`knn_channels`)
- 규칙은 백업 안전망으로 강등

**검증**: 공소청 → 미첨부 3호 정답 전환 ✅. 단일 조문 의안(국가교육위법 2125482)도 강한 매칭(0.8455) 단독 발동 조건 추가 후 정답 ✅

**부수 발견**: 이 과정에서 Supabase 프로젝트가 일시정지 상태로 **모든 RAG 검색이 무음 실패** 중이었음을 발견. 복구 후 유사도 매칭 성능이 정상화.

## 사이클 3 — 다수결의 함정과 NABO 존재 게이트

**문제**: 대구경북특별시 특별법(2216468, 325개 조문)에서 미첨부로 오답. NABO 정답은 **비용추계서 248.5억** — 재정수반요인 39개 중 29개가 추계 곤란인데도 산출 가능한 7개만으로 일부추계를 작성.

**진단**: NABO의 실제 판단 원칙은 다수결이 아니라 **존재 판정**:
> "산출 가능한 조문이 1개라도 있으면 그것만으로 일부추계. 미첨부는 산출 가능 조문이 0개일 때만."

우리 Dual-Channel은 "미첨부성 조문이 많으면 미첨부"라는 다수결이라 이 원칙과 충돌.

**개선**: 존재 게이트 도입 — 산출 가능한 조문(strong formula: 위원 정수·증원 인원·보수 명시)이 존재하면 미첨부 dominance 발동 금지.

**검증**: 각급법원 22대 개정안(2213969) → 비용추계서 **120.94억, NABO와 100% 일치** ✅. 미적재 신규 의안(친환경농어업법 2214559)도 산출 방향 정답 + 오차 21% (위원 수 가정 차이 수준) ✅

## 사이클 4 — 합계 이중계산 버그와 동일 법률 선례

**문제**: 노동위원회법 개정안(2215589)에서 121억 산출. NABO 정답은 미첨부. 게다가 121억은 실제 차용값의 정확히 2배.

**진단** (JSON 신호 추적):
1. kNN은 정답을 알고 있었음 — 같은 법 개정안의 미첨부 사유서를 0.7244로 매칭. 그러나 마진 임계값(0.08)에 0.034로 걸려 신호 폐기
2. TAG 차용 시 원본 추계서의 **"합계" 행이 개별 항목과 함께 items로 삽입**되어 금액이 2배로 계산되는 버그

**개선**:
- TAG 차용 시 합계·총계·소계 행 필터링 (이중계산 제거)
- **동일 법률 미첨부 선례** 조건 신설: 같은 법 개정안의 미첨부 사유서가 0.70+ 매칭되면 마진 조건 없이 최우선 선례로 인정

**검증**: 노동위원회법 → 미첨부 3호 정답 전환, 사유서에 "유사 미첨부 사례(노동위원회법 일부개정법률안)" 자동 인용 ✅. 사전 회귀 점검으로 각급법원 케이스에 영향 없음 확인.

**검증**: 4건 모두 `excludedCurrentBill=true`, `evidence_leak=false`.

**문제**: 근거가 없을 때 위원회 400만 원, 회의 연 2회, 연구용역 1억 원 같은 family-wide fallback이 결과를 억지로 완성함.

## 사이클 7 — 국립대학병원법의 구조 오류

**최초 결과**: 4,300만 원. 공식 결과는 1억 6,100만 원.

**진단**:
1. 위원회 설치와 구성 조문을 두 항목으로 중복 합산
2. `5년마다 발전종합계획`을 누락
3. 기존 출연금 차등지원 조문에서 신규 지원비를 생성
4. 직원 임면 규정을 인력 증원으로 해석

**개선**:
- `article/entity + formula_family` 기반 정규화·중복 제거
- 비용항목 주장을 대응 조문으로 역검증하는 grounding gate
- `N년마다`를 `periodic` 산식으로 변환
- 주제 매칭이 약할 때 UI 후보 2건이 아니라 target-excluded 공식 코퍼스 분포 사용

**검증**: 잘못된 항목이 남은 중간결과 1억 4,700만 원을 거부하고, 조문에 근거한 위원회·계획수립 두 항목만으로 1억 4,900만 원(오차 -7.5%) 산출.

### 평가 해석 시 주의사항

- `미적재`는 당시 구조화 TAG 테이블 기준이며, 관련 공식 문서가 RAG 검색 풀에도 없었다는 뜻은 아닙니다.
- 일부 사례는 오답을 확인한 뒤 정책과 임계값을 수정했으므로 일반화 성능이 아니라 회귀 확인에 가깝습니다.
- 동일 `bill_id` 정답 제외는 적용했지만, 오답을 관찰한 후 구조를 개선했으므로 독립 블라인드 성능으로 해석할 수는 없습니다.
- 금액 사례는 4건뿐이며, 방향 일치와 금액 오차를 하나의 정확도 수치로 합치지 않습니다.

## 이 기록에서 얻은 설계 원칙

1. **오답은 두 부류로 구분한다** — 데이터 부족형(사례 적재로 해결)과 로직 결함형(코드 수정 필요). 진단 없이 고치면 오버피팅이 반복된다.
2. **규칙보다 데이터** — 규칙은 케이스 하나를 잡고 다음을 놓친다. kNN 매칭은 사례가 쌓일수록 알아서 좋아진다.
3. **도메인의 실제 판단 원칙을 데이터에서 역설계한다** — "존재 게이트"는 문서 어디에도 명시돼 있지 않았고, NABO 정답지 4건을 나란히 놓고서야 도출됐다.
4. **검증은 양방향으로** — 미첨부 방향만 3연승 후 산출 방향을 처음 돌리자 즉시 오버슈팅이 드러났다. 한 방향의 개선은 반대 방향의 회귀를 의심해야 한다.

## 사이클 8 — 조직신설 비용을 구조·값·사용자 입력으로 분리

**대상 개발 사례**: 광주·전남초광역특별지방자치단체법안(2213937). 공식
추계 49,811백만원은 조직 인력운영비, 지원협의회 운영비, 조직 전체
운영예산으로 구성된다.

**문제**: 의안 전체가 비슷한 선례 하나를 고르면 서로 성격이 다른 비용항목을
한꺼번에 이전하게 된다. 반대로 항목별 숫자를 무관한 여러 선례에서 섞으면
그럴듯한 총액만 만드는 문제가 생긴다.

**개선**:

- 구조는 같은 법형식의 설치 사례에서 찾고, 금액은 같은 인사·예산 체계에서
  보수·기관부담금·기본경비·자산취득비와 인원 분모가 한 행에 완결된 단일
  선례를 선택한다.
- 여러 조직이 한 의안에 있으면 전역 인원 하나를 임의 배분하지 않고
  사건 ID·조문·조직명별 순증 인원을 받는다.
- 지원협의회는 수당 전용·실무지원단 선례를 제외하고, 지원기구 전체 운영비
  범위의 단일 선례만 허용한다.
- 조문에 조직 전체 운영경비 분담 의무가 있는데 같은 법형식의 운영예산
  선례가 없으면 0원이나 기본값을 만들지 않고 사용자 입력으로 남긴다.
- 재량적인 공사·공단 설립 조문은 조직 인건비 자동확대 대상에서 제외한다.

**개발 검증**:

| 비용항목 | 선택 근거 | 시스템 | 공식 |
|---|---|---:|---:|
| 인력운영비 | 지방자치단체 인사체계의 완결 묶음 2211844를 105명→60명 비례 | 28,364.4 | 29,546 |
| 지원협의회 | 전체 운영 범위 선례 2213471 | 260 | 265 |
| 조직 운영예산 | DB에 호환 선례 없음 → 연 4,000백만원 사용자 입력 | 20,000 | 20,000 |
| 합계 | 위 세 채널 합산 | 48,624.4 | 49,811 |

총액 오차는 -2.38%다. 이 사례의 공식 결과를 본 뒤 구조를 개선한
**개발 회귀 검증**이며 독립 블라인드 성능으로 해석하지 않는다. 런타임 코드에는
대상 의안번호나 공식 금액 분기가 없고, 대상 추계서 자체는 후보에서 제외한다.

## 사이클 9 — 모델 선택 오류와 진짜 데이터 부족 분리

**문제 1: 데이터는 있는데 모델이 잘못 선택**

- 친환경농어업발전위원회에서 법정 상한 25명과 양립하는 20명 선례를
  Solar가 “상한 초과”라고 설명하며 15명을 선택했다.
- 국립대학병원발전위원회 PDF의 `25인이 내` 줄바꿈을 산식 게이트가
  복원하지 못해 50명 선례가 후보에 남았다.

**구조 개선**

- 선택 산식의 직접 관측 인원은 정원·구성 게이트를 통과하면 생성 모델보다
  먼저 사용한다.
- 산식·변수 단계가 같은 공백 제거 방식으로 법정 정원을 읽는다.
- 수당 단가는 위원회 이름보다 최신 정부 공통 예산·기금운용 지침의
  출처 직접성을 우선한다.
- 검색은 임베딩 의미검색을 유지하며 글자 겹침 점수를 추가하지 않았다.

**문제 2: 과거 DB에 실제 기준값이 없음**

공무원보수위원회 공식 추계는 의안 밖의 현황인 기존 지급대상 10명,
실제 수당 35만원, 연 4회를 사용한다. 대상 의안과 시간 기준 과거 DB만으로는
이 값을 복원할 수 없으므로 다른 위원회의 숫자를 억지로 복사하지 않았다.

**재사용형 HITL**

- 대상 조문에서 신규 지급가능 인원 18명을 계산
- 사용자가 기존 지급대상 10명을 확인
- Python이 순증 `18 - 10 = 8명`을 계산
- 실제 수당·회의횟수를 입력하면 즉시 5개년 재계산

입력 변수는 특정 의안 전용이 아니라 모든 위원회에서 재사용 가능한
`incumbent_paid_members`, `paid_members`, `unit_price_won`,
`annual_meetings` 계약으로 구현했다.

**피드백 수집 정책**

화면에서 확정한 값은
`backend/generated/hitl_feedback/committee_variable_feedback.jsonl`에
append-only로 저장한다. 동일 확인값은 안정 ID로 중복 제거하며,
`review_status=pending`, `eligible_for_retrieval=false`로 공식 TAG와
분리한다. 현재는 Supabase에 자동 업로드하지 않고, 아래 명령으로 검토 묶음만
생성한다.

```bash
python3 -m backend.scripts.export_hitl_feedback
```

## 사이클 10 — 총액 회귀와 산식 회귀 분리

**문제**: 총액 오차가 작아도 서로 다른 피연산자가 상쇄되어 같은
금액이 될 수 있다. 국립대학병원발전위원회의 공식은
`11명×25만원×4회`인데, 시스템은 `22명×25만원×2회`로 같은
연간 11백만 원을 만들었다.

**개선**:

- 오차율과 별개로 항목 구조·산식 형태·변수·출처를 교차 감사했다.
- 검색 정책 버전을 올릴 때 동일한 질의 임베딩까지 무효화되던
  캐시 결합을 분리했다. 질의 벡터는 임베딩 모델·질의를 기준으로
  재사용하고, 재랭킹 정책만 별도 버전으로 관리한다.
- `사무처리`의 `사무처` 부분 문자열 때문에 발전기금을 인력 조직으로
  오분류하던 것을 막고, 명시적 사무국·직원 근거가 있을 때만 조직
  비용 채널로 보낸다.
- 광주전남 지원협의회는 과거 DB의 동일 법형식 2213471을 다시
  검색해 5년 260백만 원을 계산했다.
