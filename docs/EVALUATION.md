# ORCA Evaluation

> 최종 갱신: 2026-07-19  
> 목적: 개발 과정에서 발견한 오답을 특정 정답에 맞추지 않고, 일반화된 시스템 개선으로 해결했는지 기록한다.

## 1. 이 평가가 답하는 질문

1. 분석 대상 의안의 정답 추계서를 보지 않고도 결과를 만들 수 있는가?
2. 조문에 없는 비용항목이나 기본금액을 만들지 않는가?
3. 오답 수정이 특정 `bill_no`나 정답 금액에 의존하지 않는가?
4. 같은 판단·산식 로직을 여러 유형에 적용해도 금액이 합리적인 범위에 드는가?

## 2. 평가 규칙

### Target exclusion

분석 시 PDF 안의 의안번호를 추출한 뒤 아래 모든 후보 풀에서 해당 `bill_no`를 제외했다.

- 유사 비용추계서 RAG
- 유사 미첨부 사유서 RAG
- 구조화 TAG 산식·금액
- 위원 수, 회의횟수, 수당 단가 등 전제값 풀

평가 결과의 `holdout.excludedCurrentBill=true`, `evidence_leak=false`를 함께 확인했다.

### 비교 단위

- 금액 단위: 백만 원
- 오차율: `(ORCA - 공식 총액) / 공식 총액 × 100`
- 만 원 미만 단위를 백만 원으로 표시하며 보이는 연도별 합계와 총액 사이에 소수점 반올림 차이가 있을 수 있다.

## 3. 4건 홀드아웃 결과

| 의안 | 공식 총액 | ORCA | 절대오차 | 검색 누출 | 결과 구성 |
|---|---:|---:|---:|---:|---|
| 친환경농어업법 (2214559) | 120 | 100 | 16.7% | 없음 | 위원회 회의수당 5개년 |
| 간호법안 (2126640) | 20 | 24 | 20.0% | 없음 | 위원회 회의수당 5개년 |
| AI 데이터센터법 (2213320) | 318 | 316 | 0.6% | 없음 | 초기 사업비 + 연간 운영비 |
| 국립대학병원법 (2126334) | 161 | 149 | 7.5% | 없음 | 위원회 + 5년 주기 발전계획 |

- 절대오차 20% 이내: **4/4**

- 최대 절대오차: **20.0%**
- 대상 의안 근거 누출: **0/4**
- 계산·정책 단위 테스트: **44개 통과**
- Frontend: **ESLint, Vite production build 통과**

## 4. 사례 분석: 국립대학병원법

### 공식 결과

| 비용항목 | 1차년도 | 2~5차년도 | 5개년 총액 |
|---|---:|---:|---:|
| 국립대학병원발전위원회 | 11 | 각 11 | 55 |
| 국립대학병원발전종합계획 | 106 | 0 | 106 |
| 합계 | 117 | 각 11 | 161 |

### 최초 실패: 43백만 원

작은 금액을 낸 것이 문제의 본질은 아니었다. 산출물의 구조 자체가 틀렸다.

1. `위원회 설치`와 다음 `위원회의 구성` 조문을 두 비용항목으로 합산했다.
2. `5년마다 발전종합계획을 수립`하는 의무를 비용항목으로 올리지 못했다.
3. 조문은 기존 출연금을 차등하여 지원할 수 있다는 내용인데, 새로운 지원비를 만들었다.
4. 위원회 연간 운영비처럼 근거 없는 평면 기본값 경로가 남아 있었다.

### 거부한 수정: 정답 숫자에 맞추기

중간에 147백만 원이 나왔지만 결과를 채택하지 않았다. 조문에 없는 `직원 임면`을 인력비로 오판한 항목과 중복 연구용역 표현이 남아 있었기 때문이다. 오차가 작아도 잘못된 항목으로 맞은 결과는 회귀 검증으로 쓰지 않았다.

### 최종 구조: 149백만 원

#### 1) 위원회: 12백만 원/년

```text
연 4회 × 수당 지급 대상 12명 × 250,000원 = 12,000,000원/년
```

- 회의횟수: 현재 의안을 제외한 공식 위원회 사례 119건의 최빈값 `4회`
- 지급 대상: 조문상 위원 정수 25명에서 위촉·민간위원 비율을 구조적으로 반영한 12명
- 단가: 문맥상 유사한 공식 사례 2건의 중앙값 `250,000원`

주제가 강하게 일치하는 선례가 있으면 그 선례를 우선한다. 그렇지 않을 때만 짧은 UI 후보 2건이 아니라 target-excluded 전체 코퍼스 분포를 사용한다.

#### 2) 5년 주기 계획: 89백만 원

다른 공식 의안 2124409의 계획수립 연구용역 89백만 원을 선례 기준값으로 사용했다. 금액은 선례에서 가져오지만 반복 주기는 현재 조문의 `5년마다`를 사용했다.

```text
1차년도: 계획 89 + 위원회 12 = 101백만 원
2~5차년도: 위원회 각 12백만 원
5개년 총액: 101 + 12 + 12 + 12 + 12 = 149백만 원
```

## 5. 특정 의안에 맞춘 코드가 아닌 이유

런타임 분기에 `2126334`, `149백만`, `161백만`을 사용하지 않았다. 테스트의 예시 ID는 홀드아웃 제외 기능을 검증하기 위한 fixture일 뿐, 산식 선택이나 금액 보정에 쓰이지 않는다.

개선 단위는 모두 일반 개념이다.

- 분석 대상 의안 ID 제외
- 조문 기반 비용항목 grounding
- 조문·실체·산식 family 중복 제거
- `N년마다`를 해석하는 주기적 산식
- 주제 강도에 따른 지역 선례/전체 분포 선택
- 근거 없는 family-wide 금액 fallback 제거
- 미확정 변수를 대상으로 한 Human-in-the-loop

## 6. 평가 범위와 다음 벤치마크

이 결과는 정답 문서를 뺀 **target-excluded 개발 holdout**이다. 오답을 분석하며 구조를 개선한 4건의 회귀 결과이므로, 대규모 블라인드 성능과 구분해 해석한다. 다음 벤치마크는 시간 기준 독립 세트에서 아래 지표를 측정한다.

| 단계 | 지표 |
|---|---|
| 비용유발 조문 탐지 | precision, recall, F1 |
| 추계서/미첨부 판정 | macro F1, confusion matrix |
| 근거 검색 | recall@k, MRR, target leakage rate |
| 금액 | MAPE, 중앙값, 최대오차, 유형별 오차 |
| HITL | 필수 입력 수, 수정 횟수, 완료 시간 |

## 7. 재현 명령

외부 API 키와 Supabase 데이터가 준비된 환경에서 평가 스크립트를 실행한다.

```bash
python3 -m backend.scripts.evaluate_assembly_batch \
  2214559 2126640 2213320 2126334 \
  --out /tmp/orca-holdout
```

스크립트는 의안별 분석 JSON과 `summary.json`을 남긴다. 외부 LLM·임베딩 API의 모델 버전과 요청 상태에 따라 재실행 결과는 달라질 수 있으므로, 블라인드 벤치마크에서는 모델·프롬프트·데이터 버전도 함께 고정해야 한다.

## 8. 실패 후 DB 근거 감사 하네스

`run_estimator_v2`는 공식 정답표가 있는 개발용 의안을 실행한 뒤, 기본적으로
DB 미사용 근거 감사도 함께 수행한다.

```bash
python3 -m backend.scripts.run_estimator_v2 2126685
```

감사는 정답 금액을 추계 엔진에 전달하지 않는다. 정답 추계서에서 공식적으로
준용한 출처기관 이름만 평가 oracle로 읽고 다음을 확인한다.

1. 대상 의안과 같은 법률, 대상보다 미래인 의안을 후보에서 제외한다.
2. 대상보다 과거인 다른 추계서의 TAG/RAG에 같은 출처기관의 예산·실적 근거가
   있었는지 확인한다.
3. 현재 결과가 그 독립 근거를 실제로 선택했는지 확인한다.
4. 근거가 있었지만 선택하지 않았다면 `independent_evidence_missed`로 기록한다.
5. 명시적 출처기관이 없으면 데이터 부족으로 단정하지 않고
   `audit_inconclusive_no_source_anchor`로 남긴다.

판정의 의미는 다음과 같다.

| 판정 | 의미 | 다음 조치 |
|---|---|---|
| `independent_evidence_selected` | 독립적인 과거 DB 근거를 사용함 | 계산·전이 타당성 점검 |
| `independent_evidence_missed` | DB에 강한 근거가 있었지만 미사용 | 검색·인덱싱·재랭킹 개선 |
| `no_independent_source_evidence` | 공식 출처 기준 과거 DB 근거 없음 | 다른 구조 선례 탐색 후 HITL 검토 |
| `audit_inconclusive_no_source_anchor` | 공식 항목에 출처기관이 없음 | 수동 오류분해 또는 별도 검색 감사 |

### 개선 채택 규칙

오답을 발견해도 특정 의안번호·정답 금액을 런타임 조건에 추가하지 않는다.
`탐지 → 검색 → 선정 → 변수 → 계산` 중 실패 단계를 먼저 특정하고 일반 규칙만
추가한다. 수정 후에는 `backend/test_estimator_v2.py` 전체와 기존 홀드아웃을
다시 실행한다. 신규 의안의 오차가 줄어도 기존 의안의 비용항목·근거·금액이
나빠지면 개선으로 채택하지 않는다.

숫자 회귀 게이트는 현재 검증 완료된 세 시나리오를 한 번에 실행한다.

```bash
python3 -m backend.scripts.run_estimator_regression
```

- 국립대학병원 발전위원회·5년 주기 계획
- 특별지방자치단체 신설과 대상별 순증인원·운영예산
- 법원 조직 승격과 동일 사법 인사체계 비용 묶음

각 결과는 대상 의안 누출이 없어야 하며 사례별 허용 절대오차를 넘어서는 순간
명령이 실패한다. 보고서는 기본적으로
`/private/tmp/estimator_v2_regression.json`에 저장된다.

기본 모드는 `offline_cache_replay`다. 저장된 LLM·임베딩 결과만 재사용하고 캐시가
없어도 외부 API를 호출하지 않으므로 크레딧을 사용하지 않는다. 캐시가 없는 단계만
필요할 때 해당 의안 하나를 명시하여 라이브로 실행한다.

```bash
python3 -m backend.scripts.run_estimator_regression \
  --bill 2126334 \
  --live
```

전체 라이브 회귀는 여러 일반 개선을 모아 최종 채택하기 직전에만 수행한다.
